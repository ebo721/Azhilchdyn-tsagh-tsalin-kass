# Reader → ERP хоолны тоо

ERP нь `POST /api/reader/meal-counts` хүсэлтээр Reader-ийн **тухайн өдрийн, хоолны төрлийн нийт тоо**-г авна. Хүсэлт бүрт `Authorization: Bearer <token>` толгой илгээнэ. Ижил токеныг ERP талд `READER_MEAL_PUSH_TOKEN` нэртэй Secret-ээр, Reader талд өөрийн Secret-ээр тохируулах шаардлагатай. Токеныг код, чат эсвэл логт бичихгүй.

```json
{
  "records": [
    { "date": "2026-09-27", "mealType": "Өдрийн хоол", "count": 125 },
    { "date": "2026-09-27", "mealType": "Оройн хоол", "count": 97 }
  ]
}
```

- `date` нь `YYYY-MM-DD` бодит хуанлийн өдөр; `mealType` нь хоосон биш текст; `count` нь 0 буюу түүнээс их бүхэл тоо. Нэг хүсэлтэд 1–5000 бичлэг байна.
- `count` нь нэмэгдэх зөрүү бус **тухайн өдрийн эцсийн нийт тоо**. ERP өдөр + хэвийн болгосон хоолны төрлөөр нэг мөр хадгална; ижил хүсэлтийг дахин илгээхэд давхар нэмэгдэхгүй. Залруулга хийхдээ шинэ эцсийн нийт тоог дахин илгээнэ. Дахин ирээгүй бусад төрлийн мөрүүд арилдаггүй.
- Амжилттай бол `200` ба `{ "received": <тоо>, "updatedAt": <ISO хугацаа> }` буцна. Токен буруу бол `401`, ERP-д токен тохируулаагүй бол `503`, хүсэлт буруу бол `400`. Сүлжээ/серверийн түр алдааны дараа яг ижил нийт тоогоо давтан илгээж болно.
- ERP-ийн нэвтэрсэн ажилтнууд `GET /api/meal-counts?dateFrom=YYYY-MM-DD&dateTo=YYYY-MM-DD`-ээр 366 хүртэл хуанлийн өдрийг харна. Энэ нь Reader-ийн Bearer токеноор нэвтрэхгүй, ажилтны session шаарддаг.

**Одоогийн хүрээ:** ERP-ийн хүлээн авагч болон харах дэлгэц бэлэн. Reader апп тусдаа Replit төсөл тул түүний өдрийн нэгтгэл илгээгч, ажиллуулах цаг/дахин оролдох дүрэм, хоёр талын Secrets-ийг тусад нь тохируулах хүртэл автоматаар мэдээлэл ирэхгүй.
