# Ажилтны авлага, өглөг бүртгэх

Админ, нягтлан **Авлага, Өглөг** хэсгийн тухайн табаас
**Ажилтны авлага/өглөг бүртгэх** үйлдлийг сонгоно.
Идэвхтэй ажилтанг нэрээр хайж, огноо, дүн, тайлбар, харьцсан данс оруулна.
Авлага нь 1200 дансны дебет, өглөг нь 2000 дансны кредит бичилттэй;
харгалзах талд сонгосон идэвхтэй дансаар тэнцүүлнэ.
1200, 2000 дансыг харьцсан данс болгон сонгохгүй.

Хоёр төрөл нэг нийтлэг форм, серверийн бүртгэлийн хэрэгжүүлэлт ашигладаг.
Сервер хуучин `postJournalEntry` баталгаажуулалт, allocation lifecycle-ийг
ашиглаж, тэнцсэн журнал болон ажилтантай холбоотой үлдэгдлийг нэг transaction-д
үүсгэнэ. Алдаа гарвал дутуу журнал, дан үлдэгдэл үлдэхгүй.
Журналд оруулсан огноо, тайлбар нь жагсаалтад харагдаж, ажилтнаар шүүж болно.

Энэ нь цалингийн суутгал, цалин олголт, кассын төлбөр эсвэл банкны тулгалт биш.
Эдгээр эх баримт, хадгалсан цалингийн үр дүнг автоматаар өөрчлөхгүй.
Хуучин ажилтан/нийлүүлэгчийн үлдэгдлүүд хэвээр; журналын цэстэй хэрэглэгч
**Журналаар бүртгэх** үйлдлээр өмнөх олон мөртэй бүртгэлээ ашиглаж болно.

`/ar-ap` цэстэй админ/нягтлан ажилчдын жагсаалтыг зөвхөн lookup GET байдлаар
ашиглана; ажилтан засах/үүсгэх эрх нэмэгдэхгүй. Viewer бүртгэлийг зөвхөн харна.
Авлага, өглөгийн түүхтэй ажилтныг устгахгүй. Ажилтан устгах болон шинэ
өглөг үүсгэхийг нэг employee row-ийн exclusive/shared lock-оор уялдуулна:
party FK-гүй polymorphic өглөг ч устгагдсан ажилтантай үлдэхгүй.

Database schema болон migration өөрчлөгдөөгүй. Production өгөгдлийг
backfill хийхгүй; тусдаа feature PR-ийг шалгасны дараа нэгтгэнэ.

## Банкны гүйлгээнээс шууд үүсгэх

Банкны жагсаалт эсвэл банкны журналын хяналтаас **Шинэ авлага үүсгэх**
эсвэл **Шинэ өглөг үүсгэх** үйлдлийг сонгож, ажилтан/нийлүүлэгчээ заана.
Банкны **зарлага → авлага** (Dr1200 / Cr1010), банкны **орлого → өглөг**
(Dr1010 / Cr2000). Энэ нь өмнө үүссэн өрийн төлөлт биш, шинэ өр үүсгэх үйлдэл.

Огноо, дүн, тайлбарыг банкны хадгалсан гүйлгээнээс авна; формоос өөрчилж
болохгүй. Огноо нь банкны гүйлгээний огноо, үүсгэсэн өнөөдрийн огноо биш.
Банк, журнал, шинэ авлага/өглөг нэг transaction-д холбогдоно. Ижил хүсэлтийг
давтан илгээвэл шинэ өр нэмэхгүй; батлагдсаны дараа өөр тал сонговол зөрчил
гэж буцаана. Кассын нэмэлт мөр, цалингийн суутгал үүсгэхгүй.

Бараа материал/хангамж эсвэл эд хөрөнгө гэж ангилсан банкны зарлагын эх
баримтын шаардлагыг энэ үйлдлээр тойрохгүй. Бодит утга нь зээл/авлага бол
банкны жагсаалтаас ангиллыг зориудаар өөрчилсний дараа бүртгэнэ.

Админ, нягтлан үүсгэнэ; viewer зөвхөн харна. Банкны цэсээр ажилтан болон
нийлүүлэгчийн lookup жагсаалт унших нь тэдгээрийг засах эрх нэмж өгөхгүй.
Банкны журнал цуцлахад төлөгдөөгүй шинэ өр хамт буцна. Авлагыг аль хэдийн
төлсөн бол төлөлтийг хэвээр үлдээн эх журналыг шууд цуцлахыг хориглоно.
