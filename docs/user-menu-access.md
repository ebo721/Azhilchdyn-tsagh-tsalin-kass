# Хэрэглэгч үүсгэх ба хэрэглэгчийн цэс

Админ `/users` хэсгээс шинэ хэрэглэгч үүсгэнэ. Нэвтрэх нэр давхардахгүй;
нууц үг 8–128 тэмдэгттэй, зөвхөн hash хадгална. Нууц үг/hash-ийг API буцаахгүй.
Хэрэглэгч үүсгэх, засах нэг нийтлэг форм ашиглана.

## Эрхийн хязгаар

- Хэрэглэгч бүрийн цэсийг зөвхөн одоогийн role-д зөвшөөрсөн хүрээнд сонгоно.
  Цэс сонгох нь харах/засах/устгах role эрхийг нэмэхгүй.
- Хуучин `menu_paths IS NULL` хэрэглэгчдийн цэс, API эрх хэвээр.
  Хоосон `[]` нь цэсгүй хэрэглэгч; нэвтэрч, гарах боломжтой ч модуль нээхгүй.
- Цэс өөрчлөөгүй засварт default төлөвийг хэвээр үлдээнэ. “Үндсэн цэс рүү
  буцаах” нь зөвхөн checkbox бөглөх биш, default төлөв (`NULL`) рүү буцаана.
- Админы `/users` цэсийг хасахгүй. Өөрийгөө устгах болон сүүлийн админы
  эрхийг бууруулах/устгахыг хориглоно. Админ өөрчлөлтүүдийг нэг transaction
  lock-оор дараалуулж, сүүлийн админыг зэрэг өөрчилж алдахгүй.
- Explicit сонголттой хэрэглэгчийн цэс, хуудасны шууд холбоос, үндсэн API-г
  хязгаарлана. Сонгосон хуудас ажиллахад шаардлагатай shared lookup **GET**
  (цалин дахь ажилчид/кассын хаалт гэх мэт) нээлттэй үлдэнэ; lookup нь
  харгалзах модульд өөрчлөх эрх өгөхгүй. Role-ийн хуучин шалгалт давхар үйлчилнэ.
- Шинэ API нь сонголттой хэрэглэгчид анхандаа хаалттай; холбогдох цэсийг
  mapping-д нэмээд зөвшөөрөл болон dependency туршилт бичнэ.
- Засвар хадгалбал тухайн хэрэглэгчийн session хүчингүй болно, дахин нэвтэрнэ.
  Frontend session-ийг 30 секунд тутам шалгаж, хэрэглэгч солигдоход хуучин cache-г арилгана.

## Шилжилт

`20261014_user_menu_access.sql` зөвхөн nullable `users.menu_paths text[]`
багана нэмнэ. Хуучин account/нууц үг болон санхүүгийн өгөгдлийг өөрчлөхгүй.
Development-д хэрэгжүүлж шалгана; production SQL-г owner тусад нь хянаж
зөвшөөрсний дараа main-д нэгтгэнэ.

Rollback нь saved цэсийн хязгаарлалтыг **устгаж**, хуучин role default руу
буцаана. Хязгаарлалтыг backup авч, кодын rollback-тай уялдуулсны дараа л ажиллуулна.
