# Даалгавар: Журналын модуль — Хэсэг 3/4: Автомат posting холболт

> **Урьдчилсан нөхцөл**: Хэсэг 1 (schema + posting engine) болон Хэсэг 2 (Журналын API) `main`-д мержигдсэн байх ёстой. Ажил эхлэхийн өмнө repo-ийн язгуур дахь `AGENTS.md`-г заавал унш.

## Зорилго

Кассын гүйлгээ, цалингийн төлбөр, бараа материал/үндсэн хөрөнгийн худалдан авалт **баталгаажих мөчид нь шууд, автоматаар** journal entry үүсгэдэг болгох.

## ЗААВАЛ дагах хязгаарлалт

- Одоо байгаа route-уудын **бизнес логикийг өөрчлөхгүй** — зөвхөн журналын posting-ийг нэмж холбоно (одоо байгаа гүйлгээ хэвийн үргэлжилнэ, зөвхөн нэмэлтээр journal entry давхар үүснэ).
- Branch: `feature/gl-journal-03-auto-posting`.
- Journal posting нь тухайн route-ийн **яг ижил DB transaction дотор** байх ёстой — posting амжилтгүй бол route-ийн бүх өөрчлөлт rollback хийгдэнэ (мөнгөн гүйлгээ журналгүйгээр орж болохгүй).
- Алхам бүрийг тусдаа commit болго, эх сурвалж тус бүрийг нэг нэгээр нь хий (`pnpm run typecheck` дараа бүрт).

## Касс тухай тодруулга

`cash_transactions` хүснэгт нь зөвхөн "бэлэн мөнгөний хайрцаг" биш — **бэлэн мөнгөн урсгалын тайлан** (эхний үлдэгдэл → орлого → зарлага → эцсийн үлдэгдэл) гэж ойлго. Банкны гүйлгээ худалдан авалт/зардалтай **холбогдмогц** (одоо байгаа `cash_transactions.bankTransactionId`, эсвэл `operating_expenses`/`inventory_purchases`-ийн `bankTransactionId` холбоос) энэ тайланд орно.

## Автомат posting дүрэм

Дараах route handler-үүдийн дотор, гүйлгээ амжилттай хадгалагдсаны дараа (мөн адил transaction дотор) `lib/journal-posting.ts`-ийн `postJournalEntry`-г дуудна:

| Эх сурвалж | Route (одоо байгаа, өөрчилнө) | Journal бичилт (жишээ) | `sourceType` / `sourceId` |
|---|---|---|---|
| Кассын орлого | `POST /cash/transactions` (type=income) | Дебит: Касс, Кредит: тухайн `accountId`-тай холбогдсон орлогын данс | `"cash"` / cash_transactions.id |
| Кассын зарлага | `POST /cash/transactions` (type=expense) | Дебит: тухайн `accountId`, Кредит: Касс | `"cash"` / cash_transactions.id |
| Цалингийн төлбөр | `PUT /payroll-advance/payment` | Дебит: Цалингийн зардал (эсвэл Төлөх цалин өглөг), Кредит: Касс/Банк | `"payroll"` / payroll_advance_approvals.id |
| Бараа материал худалдан авалтын төлбөр | `PUT /inventory/purchases/:id/payment` | Дебит: Бараа материал (эсвэл тухайн зардлын данс), Кредит: Касс/Банк | `"inventory_purchase"` / inventory_purchases.id |
| Үндсэн хөрөнгө худалдан авалт | `POST /fixed-assets` (`purchased: true` үед), `PUT /fixed-assets/:id` (`purchased` false→true болох үед) | Дебит: Үндсэн хөрөнгө, Кредит: Касс/Банк/Өглөг | `"fixed_asset"` / fixed_assets.id |

**Давхар бичихээс сэргийлэх**: Банкны гүйлгээ нь `cash_transactions`, `operating_expenses`, `inventory_purchases` ямар нэгэн хэлбэрээр **холбогдсоны дараа** л journal entry үүснэ — банкны гүйлгээ өөрөө шууд journal үүсгэдэггүй. Тухайн route (жишээ нь `link-cash`) нь эцэст нь эдгээр хүснэгтийн аль нэгэнд бичдэг тул posting hook нь тэр цэг дээр ажиллана — банкны route дотор тусад нь дахин posting хийхгүй.

**Аль accountId-г ашиглах вэ**: Хэрэв route-д ирэх body-д `accountId` байхгүй бол (жишээ нь цалингийн төлбөрт тодорхой "Цалингийн зардал" данс урьдчилж chart_of_accounts дээр байх ёстой) — эхний ажиллуулалтад `chart_of_accounts`-д шаардлагатай стандарт дансдыг seed script-ээр нэмж өг (жишээ нь: "Касс", "Банк", "Цалингийн зардал", "Төлөх цалин өглөг"). Seed script-ийг `lib/db/src/seed-journal-accounts.ts` (эсвэл төстэй нэрээр) бичиж, migration-той хамт ажиллуулна.

## Гүйцэтгэх дараалал

1. `git checkout -b feature/gl-journal-03-auto-posting` (`main`-аас, Хэсэг 1,2 мержигдсэний дараа)
2. Стандарт дансдын seed script (Касс, Банк, Цалингийн зардал гэх мэт) → commit
3. Кассын гүйлгээнд (`cash/transactions` POST) posting холбох → typecheck → бодит гүйлгээгээр туршиж, `/journal/trial-balance` дээр тэнцэж байгааг харах → commit
4. Цалингийн төлбөрт posting холбох → commit
5. Бараа материалын худалдан авалтын төлбөрт posting холбох → commit
6. Үндсэн хөрөнгийн худалдан авалтад posting холбох → commit
7. PR нээж шалгуулаад мержил
